# НАИМЕНОВАНИЕ <!-- help:skip -->

coole - текстовый редактор.

# СИНТАКСИС <!-- help:skip -->

**coole**
[ключи] [+строка] [файл1[:строка]] [файл2[:строка]] ...

# ОПИСАНИЕ <a id="description"></a>

**coole**
\- консольный текстовый редактор. Он продолжает
**cooledit**,
редактор Пола Шира (Paul Sheer), терминальная версия которого много лет
развивалась как встроенный редактор GNU Midnight Commander; coole развивает
этот редактор дальше как самостоятельную программу.

Он правит несколько файлов сразу, каждый в своем окне, и умеет править
двоичные файлы. В нем есть копирование, перемещение, удаление, вырезание и
вставка блоков; отмена и повтор операций клавиша за клавишей; выпадающие
меню; вставка файла; макросы; поиск и замена по регулярным выражениям;
фильтр строк; свертка; закладки; выделение текста клавишами со стрелками и
Shift (если терминал их различает); вертикальные блоки; режимы вставки и
замены; автоотступ; перенос слов и форматирование абзацев; настраиваемый
размер табуляции; подсветка синтаксиса для многих типов файлов; меню
пользователя, передающее текст через команды оболочки; плагины редактора
(навигация по тегам, проверка правописания) и скрипты на Lua.

Каждый файл из командной строки открывается в своем окне. Без файлов
редактор открывает пустое окно. Файл больше, чем
*editor_filesize_threshold*
(по умолчанию 64 Мбайта), открывается после вопроса, а не отвергается.

# ОПЦИИ <a id="options"></a>

*+номер*
: Перейти к строке с этим номером (между знаком
*+*
и числом не должно быть пробела). Номеров можно указать несколько, но взят
будет последний, и только для первого файла.

*файл:номер[:]*
: Открыть файл на этой строке - так место в файле печатают компиляторы и
grep. Если существует файл с таким полным именем, вместе с двоеточием и
числом, открывается он.

*-V, --version*
: Показать версию программы.

*-f, --datadir*
: Показать вкомпилированные пути поиска файлов данных coole.

*-F, --datadir-info*
: Показать подробные сведения о каталогах, с которыми работает coole: о
файлах данных, файлах пользователя и плагинах.

*--configure-options*
: Показать ключи, с которыми программа была сконфигурирована.

*--no-lua*
: Запуститься без среды Lua: ни один Lua-скрипт не загружается.

*-h, -?, --help*
: Показать ключи и то, что они делают.

*--help-terminal, --help-color*
: Показать ключи терминала или ключи цвета, описанные ниже.

Ключи терминала:

*-x, --xterm*
: Включить режим xterm. Применяется на терминалах, которые умеют то же, что и
xterm: два режима экрана и последовательности мыши.

*-X, --no-x11*
: Не обращаться к X Window System за состоянием клавиш-модификаторов.

*-g, --oldmouse*
: Использовать старый способ отслеживания мыши терминалом.

*-d, --nomouse*
: Отключить поддержку мыши.

*-t, --termcap*
: Брать сведения о терминале из termcap, а не из terminfo. Ключ есть только
тогда, когда coole собран с библиотекой S-Lang.

*-s, --slow*
: Работа на медленном терминале: экран перерисовывается реже.

*-a, --stickchars*
: Рисовать рамки простыми символами вместо псевдографики терминала.

*-K файл, --keymap=файл*
: Загрузить привязки клавиш из этого файла. Смотрите
[Переопределение клавиш](#keys_redefine).

*--nokeymap*
: Не загружать никаких файлов раскладки: использовать привязки клавиш,
встроенные в программу.

Ключи цвета:

*-b, --nocolor*
: Черно-белый режим отображения.

*-c, --color*
: Цветной режим на терминалах, которые не сообщают о поддержке цвета.

*-S скин, --skin=скин*
: Использовать скин с этим именем. Смотрите
[Скины](#skins).

# Общий вид <a id="overview"></a>

Вверху экрана coole находится
[строка меню](#menu-bar),
под ней окна редактора, а внизу - надписи функциональных клавиш. Строка меню
может быть скрыта: F9 или щелчок по верхней строке экрана вызывают ее.

В каждом окне показан один файл: его имя, состояние файла и положение
курсора стоят в строке состояния вверху окна. Окон может быть открыто
несколько; меню
[Окно](#window-menu)
переключает их, а каждое окно можно двигать и менять его размер.

# Редактор <a id="internal-file-editor"></a>

Редактор прост и не требует обучения. Выпадающее меню открывает F9, а
клавиши команд написаны рядом с ними в меню и на надписях функциональных
клавиш.

Разделы:
: [Клавиши](#keys)
: [Меню](#menu-bar)
: [Поиск, замена и фильтр строк](#search-and-replace)
: [Свертка](#folding)
: [Макросы](#macros)
: [Меню пользователя](#edit-menu-file)
: [Навигация по коду](#code-navigation)
: [Подсветка синтаксиса](#syntax-highlighting)
: [Настройки редактора](#editor-options)
: [Параметры в ini-файле](#internal-file-editor-options)

Каждый файл открывается в своем окне на весь экран. Окнами управляют так же,
как в других многооконных программах: двойной щелчок по заголовку окна
разворачивает его на весь экран или возвращает прежний размер и положение;
нажатие левой кнопкой на заголовке и перетаскивание двигают окно; нажатие
на правом нижнем углу рамки и перетаскивание меняют размер. То же самое
делается из меню
[Окно](#window-menu).

Shift со стрелками выделяет текст (если терминал их различает).
**Ctrl-Ins**
копирует в файл обмена
**~/.local/share/coole/clipboard**,
**Shift-Ins**
вставляет из него,
**Shift-Del**
вырезает в него, а
**Ctrl-Del**
удаляет выделенный текст. Работает и выделение мышью, а если при
протягивании держать Shift, то выделение делает сам терминал; такое
выделение не попадает в файл обмена coole.

**Ctrl-o**
показывает внизу экрана окно с вашей оболочкой, а файл - в окне над ним, и
снова прячет его таким, как оно есть, возвращая файлу весь экран; смотрите
[Терминал](#terminal).

# Клавиши <a id="keys"></a>

В некоторых командах используются клавиши
*Control*
(иногда обозначаемая CTRL или CTL) и
*Meta*
(иногда обозначаемая ALT или даже Compose). В этом руководстве используются
такие сокращения:

**Ctrl-\<символ>**
: означает, что нужно держать клавишу Control и нажать \<символ>. Так, Ctrl-f
\- это нажатие f при нажатой клавише Control.

**Alt-\<символ>**
: означает, что нужно держать клавишу Meta или Alt и нажать \<символ>. Если
клавиш Meta и Alt нет, нажмите
*Esc,*
отпустите ее, а затем нажмите \<символ>.

**Shift-\<символ>**
: означает, что нужно держать клавишу Shift и нажать \<символ>.

Здесь перечислены клавиши редактора по умолчанию. Любую из них можно
поменять: смотрите
[Переопределение клавиш](#keys_redefine).

## Переопределение клавиш <a id="keys_redefine"></a>

Диалог
[Привязки клавиш](#key-bindings)
меню "Настройки" показывает каждое действие с клавишами, на которые оно
отвечает, меняет их и записывает результат в
**~/.config/coole/keymap.ini**.
Диалог
[Распознавание клавиш](#learn-keys)
решает задачу с другого конца: он учит программу последовательностям,
которые терминал посылает для клавиш, распознаваемых неверно.
[Анализатор клавиш](#key-sniffer)
показывает, что приходит при нажатии клавиши, и какое действие на нее
назначено в текущей раскладке - туда и нужно смотреть, когда привязка будто
бы ничего не делает.

Привязки клавиш можно читать и из файла раскладки. Программа начинает с
раскладки, встроенной в ее исходный код. Затем всегда загружаются файлы
**{{pkgdatadir}}/keymap.ini**
и
**{{sysconfdir}}/coole/keymap.ini**,
каждый переназначает клавиши, заданные раньше. Пакет кладет свои раскладки
в
**{{sysconfdir}}/coole**:
**keymap.default.ini**,
**keymap.emacs.ini**
и
**keymap.vim.ini**,
а
**keymap.ini**
\- ссылка на раскладку по умолчанию. Ключ
**--nokeymap**
не загружает ни одного файла и оставляет привязки из исходного кода.

Файл раскладки пользователя - первый найденный из:

```
1) ключ командной строки -K <раскладка>, --keymap=<раскладка>
2) переменная окружения COOLE_KEYMAP
3) параметр keymap секции [coole] ini-файла
4) файл ~/.config/coole/keymap.ini
```

Первые три принимают имя или абсолютный путь. К имени, которое не
оканчивается на
**.keymap**,
добавляется это расширение, и файл ищется в (до первого найденного):

```
1) ~/.config/coole/
2) {{pkgdatadir}}/
```

Из-за этого расширения раскладки пакета, имена которых оканчиваются на
**.ini**,
так выбрать нельзя. Чтобы взять одну из них, скопируйте ее или сделайте на
нее ссылку
**~/.config/coole/keymap.ini**,
который читается последним и не требует ключей:

```
ln -s {{sysconfdir}}/coole/keymap.vim.ini \
      ~/.config/coole/keymap.ini
```

В файле раскладки есть секция редактора,
**[editor]**,
секция клавиш, которые идут после Ctrl-x,
**[editor:xmap]**,
и по секции для диалогов, меню, строк ввода, списков, переключателей и окна
помощи. Строка секции называет действие и клавиши, на которые оно отвечает:

```
[editor]
Save = f2
SaveAs = f12; ctrl-f2
```

# Поддержка мыши <a id="mouse-support"></a>

coole поддерживает мышь. Она работает всегда, когда программа запущена в
терминале
**xterm(1)**
(даже если из xterm открыто соединение telnet или ssh с другой машиной) или
на консоли Linux с запущенным сервером мыши
**gpm**.

Щелчок ставит курсор в место щелчка, перетаскивание выделяет текст, а щелчок
по меню, кнопке или надписи функциональной клавиши выбирает ее. Колесо
прокручивает текст.

По умолчанию кнопки мыши повторяют нажатие каждые 400 миллисекунд. Это
значение меняет параметр
*mouse_repeat_rate*
ini-файла, а время, в пределах которого два щелчка считаются двойным, -
параметр
*double_click_speed*.

Если coole работает с поддержкой мыши, обычное поведение мыши терминала
(выделение и вставка текста) получается при нажатой клавише Shift.

### Настройки редактора <a id="editor-options"></a>

Настройки редактора, которые открывает пункт
**Общие...**
меню "Настройки". Они записываются в ini-файл под именами, описанными в
разделе
[Параметры в ini-файле](#internal-file-editor-options).

*Режим переноса строк.*
Выключен, динамическое форматирование абзаца или перенос "как на пишущей
машинке", который разрывает строку по заданной длине прямо при наборе.

*Имитация неполных табуляций.*
Между текстом и левым полем перемещение и отступ идут на половину табуляции
и заполняются пробелами, а в остальных местах табуляция остается обычной.

*Забой (backspace) на табуляциях.*
Одно нажатие Backspace удаляет весь отступ до левого поля, если между
курсором и полем нет текста.

*Заполнять табуляции пробелами.*
Вместо символа табуляции вставляются пробелы до следующей позиции табуляции.

*Ширина табуляции.*
Ширина, которую занимает символ табуляции. По умолчанию 8; другие редакторы
и программы просмотра тоже считают ее равной 8.

*Автоотступ по Enter.*
Новая строка начинается с тем же отступом, что и строка выше.

*Подтверждать запись файла.*
Перед записью файла выдается запрос.

*Запоминать позицию в файле.*
Файл открывается на том месте, где его оставили в прошлый раз.

*Показывать пробелы в конце строк.*
Пробелы в конце строки отмечаются.

*Показывать табуляции.*
Символы табуляции отмечаются.

*Показывать управляющие символы.*
Управляющие символы текста печатаются, а не скрываются.

*Подсветка синтаксиса.*
Текст раскрашивается по правилам синтаксиса для его типа файла.

*Курсор после вставленного блока.*
После вставки блока курсор остается в его конце, а не в начале.

*Постоянные блоки.*
Выделение сохраняется при перемещении курсора, а не снимается.

*Курсор за концом строки.*
Курсор может стоять за последним символом строки.

*Групповая отмена.*
Одна отмена возвращает целую серию однотипных изменений, а не одно нажатие.

*Длина строки для переноса.*
Колонка, по которой режимы переноса разрывают строку. По умолчанию 72.

*Ожидание после Esc, мс.*
Сколько миллисекунд одиночный Esc ждёт продолжения клавиши, прежде чем
считаться нажатием Esc. По умолчанию 1000. В ini-файл пишется как
*old_esc_mode_timeout*,
в микросекундах, а переменная
**KEYBOARD_KEY_TIMEOUT_US**
при запуске редактора имеет приоритет.

### Режим сохранения <a id="edit-save-mode"></a>

Как записывается файл - те же три режима, что принимает параметр
*editor_option_save_mode*:

**Быстрое сохранение**
: Сразу писать поверх файла. Быстро, но сбой в середине оставляет файл
записанным наполовину.

**Безопасное сохранение**
: Сначала писать во временный файл и переименовать его поверх исходного, когда
он записан целиком, поэтому сбой не портит оригинал.

**Создавать резервные копии с расширением**
: Безопасное сохранение, и оригинал сохраняется под своим именем с
добавленным расширением из строки ввода, по умолчанию "~". Вторая запись
заменяет и резервную копию.

**Проверять перевод строки POSIX**
: Спрашивать о недостающем переводе строки в конце файла перед записью.

### Внешний вид <a id="appearance"></a>

Скин, которым рисуется программа, и то, отбрасывают ли тень диалоги и
выпадающие меню.

**Скин**
: Кнопка открывает список установленных скинов и скинов пользователя;
выбранный применяется сразу.

**Тени**
: Рисовать тень под каждым диалогом и выпадающим меню. Без цвета теней нет.

Выбор записывается в параметры
*skin*
и
*shadows*
ini-файла. О самих файлах скинов говорит раздел
[Скины](#skins).

### Распознавание клавиш <a id="learn-keys"></a>

Этот диалог учит coole управляющим последовательностям, которые терминал
посылает для функциональных клавиш, стрелок и клавиш перемещения. В его
заголовке стоит имя терминала из переменной
**TERM**.

Выберите сочетание модификаторов (Ctrl, Alt, Shift) флажками, затем нажмите
кнопку клавиши. Нажмите эту клавишу на клавиатуре и подождите, пока не
пропадет сообщение о захвате. Выученная последовательность появится рядом с
кнопкой. Если такая последовательность уже есть у другой клавиши, об этом
сообщается как о конфликте.

**Del**
: Забыть выученную клавишу, на которой стоит курсор.

**Сохранить**
: Записать выученные клавиши в
*~/.config/coole/term/\<TERM>*.

**Правка файла терминала**
: Открыть этот файл в редакторе.

### Привязки клавиш <a id="key-bindings"></a>

Действия программы с клавишами, на которые они отвечают, в таблице. Кнопки
вверху выбирают группу, Редактор или Виджеты, а затем ее часть: Основные и
Ctrl-X для редактора; Диалог, Меню, Ввод, Список, Переключатель и Помощь для
виджетов. Кнопка Назад возвращает к группам. Действия, отмеченные \*, имеют
клавиши, отличные от исходных.

**Enter**
: Заменить клавишу действия: нажмите клавишу, которую нужно назначить.

**F5**
: Добавить действию еще одну клавишу.

**F8, Del**
: Удалить клавишу.

**Сохранить**
: Записать изменения в
*~/.config/coole/keymap.ini*.

**Правка файла раскладки**
: Открыть
*keymap.ini*
в редакторе.

**Правка файла терминала**
: Открыть последовательности клавиш терминала - файл, который пишет
[Распознавание клавиш](#learn-keys).

Если клавиша занята другим действием, об этом сообщается и задается вопрос,
забрать ли ее оттуда.

### Анализатор клавиш <a id="key-sniffer"></a>

Нажмите
**Захватить клавишу**,
затем любую клавишу. Диалог покажет, что пришло:

```
Сочетание      символьное имя, например Ctrl-F5
Действие       действие клавиши в раскладке редактора
Последов.      управляющая последовательность и ее байты
Код клавиши    внутренний числовой код
```

Сюда стоит смотреть, когда клавиша ничего не делает или делает не то:
клавишу, которая приходит последовательностью, не распознанной программой,
нужно выучить в диалоге
[Распознавание клавиш](#learn-keys),
а ту, что приходит, но не имеет действия, - назначить в диалоге
[Привязки клавиш](#key-bindings).

### Управление плагинами <a id="manage-plugins"></a>

Плагины, которые загрузила программа, в таблице: вид, имя и то, что плагин
говорит о себе. Здесь перечислены плагины редактора, а если coole собран с
Lua, то и движок Lua как плагин вида
*runtime*.
Плагин выключается и включается флажком в своей строке, и выключенный

Выключенный плагин остается в списке, чтобы его можно было включить снова.

**Enter, F4**
: Открыть настройки плагина, на котором стоит курсор. Плагин без настроек

### Сведения о плагинах <a id="plugin-info"></a>

[Управление плагинами](#manage-plugins).

### Lua-скрипты <a id="lua-scripts"></a>

Найденные Lua-скрипты, системные и пользователя, в таблице: включен ли

# Поиск, замена и фильтр строк <a id="search-and-replace"></a>

Диалог поиска
(**F7**)
принимает искомый текст и тип поиска: обычная строка, регулярное
выражение, шестнадцатеричные байты или шаблон оболочки; важен ли регистр;
искать ли назад, только в выделенном блоке или целые слова; и искать ли во
всех кодировках, в которых может быть записан файл. Кнопка
**Найти все**
ставит закладку на каждой строке с совпадением. Диалог замены
(**F4**)
принимает еще и текст для подстановки и спрашивает о каждом совпадении,
если не велено заменить все сразу. При замене по регулярному выражению \\1
\- \\9 означают группы совпадения.

Кнопка
**Фильтр**
диалога поиска скрывает все строки, в которых нет искомой строки; используются
те же настройки типа поиска, регистра и целых слов, что и при поиске. Номера
строк остаются исходными, а в колонке состояния строк отмечается каждый
скрытый участок. Набор скрытых строк фиксируется в момент нажатия кнопки:
при редактировании условие заново не проверяется, поэтому видимая строка,
разрезанная или склеенная с соседней, остается видимой, и набранные после
этого строки тоже остаются видимыми, даже если под условие не подходят.
**Alt-s**
снимает фильтр; повторное нажатие снова накладывает последний поиск как
фильтр.
**Alt-Shift-s**
сразу фильтрует по выделенному тексту или по слову под курсором. Пункт
"Развернуть всё" в меню "Команда" тоже снимает фильтр.

# Свертка <a id="folding"></a>

Свертка прячет ряд строк за их первой строкой, которая остается на экране с
отметкой в колонке состояния строк.
**Alt-Shift-f**
(пункт "Свернуть / развернуть блок" меню "Команда") сворачивает выделенные
строки, а если ничего не выделено, - строки от скобки в текущей строке до
парной к ней. На первой строке свертки эта клавиша ее разворачивает.
**Развернуть всё**
открывает все свертки файла и снимает фильтр строк.

# Макросы <a id="macros"></a>

Чтобы задать макрос, нажмите
**Ctrl-r**
и наберите те клавиши, которые должны выполняться. Нажмите
**Ctrl-r**
еще раз, когда закончите, и назначьте макрос на клавишу, нажав ее. Макрос
вызывается этой клавишей, а также сочетанием
**Ctrl-a**
и назначенной клавиши.

Макросы хранятся в секции
**[editor]**
файла
**~/.local/share/coole/macros**,
и удаляются удалением своей строки в нем или в
[Обозревателе макросов](#macro-explorer).

Пункт
**Записать/повторить действия**
меню "Команда" записывает последующие действия, пока его не выберут снова,
а затем спрашивает, сколько раз их повторить.

На клавишу можно назначить и скрипт оболочки, строкой файла
**macros**
такого вида:

```
[editor]
ctrl-W=ExecuteScript:25;
```

Это значит, что Ctrl-W запускает действие
*ExecuteScript(25)*,
которое выполняет скрипт оболочки
**~/.local/share/coole/macros.d/macro.25.sh**.
Скрипты лежат в каталоге
**~/.local/share/coole/macros.d/**
и называются
**macro.XXXX.sh**,
где
**XXXX**
\- число от 0 до 9999. Примеры установлены в
**{{pkgdatadir}}/examples/macros.d/**.
Скрипт записывается в формате пунктов
[меню пользователя](#edit-menu-file)
и принимает те же подстановки. Его первой строкой может быть

*#silent*
: Скрипт запускается, не спрашивая параметров.

Вот пример скрипта:

```
l       comment selection
	TMPFILE=`mktemp ${COOLE_TMPDIR:-/tmp}/up.XXXXXX` || exit 1
	echo #if 0 > $TMPFILE

	echo #endif >> $TMPFILE

```

# Меню пользователя <a id="edit-menu-file"></a>

Меню пользователя
(**F11**)
\- это меню полезных действий, которое пользователь настраивает сам: каждый
пункт - это скрипт оболочки, который выполняется над текстом редактора.
Меню читается из первого найденного файла:

```
1) ./.coole.menu в текущем каталоге
2) ~/.config/coole/menu
3) ~/coole.menu
4) {{sysconfdir}}/coole/coole.menu
5) {{pkgdatadir}}/coole.menu
```

Файл текущего каталога читается, только если он принадлежит пользователю или
root и никто другой не может в него писать, потому что его пункты выполняют
команды. Пункт
**Файл меню**
меню "Настройки" открывает файл меню в редакторе.

Формат файла меню очень прост. Строки, которые начинаются с чего угодно,
кроме пробела и табуляции, - это пункты меню (чтобы пользоваться ими как
горячими клавишами, первым символом лучше ставить букву). Все строки,
начинающиеся с пробела или табуляции, - это команды, которые выполняются
при выборе пункта. Комментарии начинаются с '#'.

При выборе пункта все его строки команд копируются во временный файл, и
этот файл выполняется оболочкой. Поэтому в меню можно пользоваться обычными
конструкциями оболочки. Кроме того, перед выполнением кода меню делаются
простые подстановки:

*%f, %p*
: Имя текущего файла.

*%n*
: Имя текущего файла без расширения.

*%x*
: Расширение имени текущего файла.

*%d*
: Текущий каталог.

*%c*
: Положение курсора в файле.

*%i*
: Отступ из пробелов, равный колонке курсора.

*%y*
: Тип синтаксиса текущего файла.

*%b*
: Файл блока: выделенный текст записывается в
*~/.cache/coole/block*
перед запуском команды, а то, что команда оставит там, после нее заменяет
блок.

*%m*
: Имя файла меню.

*%%*
: Символ %.

*%{какой-то текст}*
: Запрос подстановки. Показывается строка ввода, а текст в фигурных скобках
служит подсказкой. Вместо макроса подставляется то, что введет
пользователь. Отменить ввод можно клавишами Esc или F10.

*%view*
: Выполнить команды и открыть их стандартный вывод в новом окне редактора.
Слова в фигурных скобках после %view, как в %view{ascii}, принимаются и
пропускаются.

Заглавные и строчные макросы означают одно и то же. Число после знака %
включает (по умолчанию) и выключает экранирование: %f и %1f экранируют
подставленное значение, %0f - нет.

Вот пример файла меню:

```
s       Sort the block
	sort %b > %b.tmp && mv -f %b.tmp %b

w       Count the words of the file
	%view wc %f

m       Run make in the directory of the file
	make
```

**Условия выбора по умолчанию**

Перед каждым пунктом меню может стоять условие. Оно должно начинаться с
первой колонки символом '='. Если условие истинно, пункт становится пунктом
по умолчанию.

```
Синтаксис условия:  = <подусловие>
  или:              = <подусловие> | <подусловие> ...
  или:              = <подусловие> & <подусловие> ...

Подусловие - одно из:

  y <шаблон>    синтаксис текущего файла подходит?
  f <шаблон>    текущий файл подходит под шаблон?
  d <шаблон>    текущий каталог подходит под шаблон?
  t <тип>       текущий файл этого типа?
  x <имя>       этот файл исполняемый?
  ! <подусл.>   отрицание подусловия
```

Шаблон - это обычный шаблон оболочки или регулярное выражение, смотря по
параметру
*shell_patterns*.
Общее значение этого параметра можно переопределить, написав
"shell_patterns=x" в первой строке файла меню (где "x" - 0 или 1).

Тип - это один или несколько из следующих символов:

```
  n   не каталог
  r   обычный файл
  d   каталог
  l   ссылка
  c   символьное устройство
  b   блочное устройство
  f   FIFO (канал)
  s   сокет
  x   исполняемый файл
```

Например, 'rlf' означает обычный файл, ссылку или FIFO.

Если условие начинается с '=?' вместо '=', при каждом его вычислении
показывается отладочная трассировка.

Условия вычисляются слева направо. Это значит, что

```
	= f *.c | f *.h & y C
```

вычисляется как

```
	( (f *.c) | (f *.h) ) & (y C)
```

**Условия добавления**

Если условие начинается с '+' (или '+?') вместо '=' (или '=?'), это условие
добавления. Если оно истинно, пункт включается в меню, если ложно - не
включается.

Условия по умолчанию и добавления можно совместить, начав условие с '+=' или
'=+' (или '+=?' и '=+?' для трассировки). Если нужны два разных условия, одно
для добавления, другое для выбора по умолчанию, перед пунктом можно поставить
две строки условий: одну с '+', другую с '='.

# Навигация по коду <a id="code-navigation"></a>

Редактор находит определение имени в файле тегов с помощью одного из двух
плагинов.

Плагин etags читает файл
**TAGS**
проекта в формате Emacs, который строит etags или
*ctags -e*.
Например, для exuberant-ctags и языка C:

```
ctags -e --language-force=C -R ./
```

**Alt-Enter**
показывает список определений имени под курсором (курсор должен стоять в
конце слова); если определение одно, редактор сразу переходит к нему.
Смотрите
[Definitions](etags.md#definitions).

**Alt-Minus**
переходит к предыдущему месту в списке навигации (как кнопка "Назад" в
браузере), а
**Alt-Plus**
\- к следующему (как кнопка "Вперед").

Плагин ctags читает файл
**tags**
программы ctags и наполняет меню "Навигация": переход к объявлению, поиск
ссылок, дополнение символа, символы файла, члены класса или структуры и
другое. Смотрите
[Ctags](ctags.md#ctags).

Оба плагина можно выключить в диалоге
[Управление плагинами](#manage-plugins),
и тогда их клавиши ничего не делают.

# Терминал <a id="terminal"></a>

Плагин терминала запускает вашу оболочку в окне редактора.
**Ctrl-o**
показывает окно внизу экрана, а развёрнутый файл переходит в окно над ним; в

разворачивают на весь экран и закрывают так же, как окно файла. Смотрите
[Terminal](terminal.md#terminal).

# Preview <a id="preview"></a>

Плагин просмотрщика показывает файл так, как его задумано читать, каким бы
ни был файл, в окне Preview справа от него.
**Ctrl-Alt-p**
или пункт Preview меню "Плагины" показывает и прячет его. Фокус остаётся в
файле; Preview перерисовывается по мере правки, следует за курсором и
показывает окно файла, которое выходит вперёд. Окно двигают, меняют его
размер и закрывают так же, как окно файла, а прокручивают клавишами
редактора, в том числе вбок для того, что шире окна. Клавиша задаётся в
**viewer.ini**,
секция
**[Preview]**,
параметр
**key**.

Рендеры сообщают просмотрщику, какие файлы они рисуют, по окончанию имени или
по началу текста, и просмотрщик отдаёт файл рендеру его типа:
markdown-файл выходит с заголовками, списками, таблицами с линиями, блоками
кода в цветах редактора, формулами символами и диаграммами mermaid рисунками;
этот рендер — Lua-скрипт render-markdown, lua-markdown из Midnight
Commander, его настройки, из диалога "Управление плагинами", хранятся в
**~/.config/coole/render-markdown.ini**.
JSON-файл, и JSON Lines тоже, выходит по значению на строку в тех цветах,
которыми редактор раскрашивает JSON, с размером каждого объекта и массива,
длинный массив уложен по ширине или сокращён, массив однотипных объектов
нарисован таблицей; комментарии и запятая перед закрывающей скобкой
допускаются. Пока файл не читается как JSON, посреди правки, сверху
показывается ошибка и её место, а под ней последний удачный вид. Этот рендер —
Lua-скрипт render-json.
Файл типа, которого не знает ни один рендер, показывается как его текст.

Кроме редактора, Lua-скрипт может открывать свои экраны - полноэкранные

**Alt-{**

Пусть программа печатает за вас.

В редакторе
**Alt-Tab**
дополняет слово перед курсором словами из файла, а при включенном параметре
*editor_wordcompletion_collect_all_files*
(по умолчанию включен) - и из других открытых файлов. Если подходит
несколько слов, появляется их список для выбора.

В строке ввода диалога
**Alt-Tab**
пытается дополнить текст как переменную (если текст начинается с
**$**),
имя пользователя (если он начинается с
**~**)
или имя файла. Если дополнение неоднозначно, программа пищит, а при

*show_all_if_ambiguous*
рядом с курсором появляется список всех вариантов: выберите вариант
стрелками и
**Enter**
или наберите первые буквы, которыми варианты различаются, чтобы сузить

можно и клавишами Esc, F10 и стрелками влево и вправо.

Список кодовых страниц, которые знает программа, из файла

**Alt-e**
и пункт "Кодировка" меню "Команда".

Список того, что раньше вводилось в строку ввода, новое сверху. Его открывает
**Alt-h**
для той строки, в которой стоит курсор. Enter берет в строку запись, на

# Подсветка синтаксиса <a id="syntax-highlighting"></a>

**coole**
умеет подсвечивать синтаксис: ключевые слова и контексты (комментарии C,
строковые константы и прочее) показываются разными цветами. Ниже описан
формат файла
**~/.local/share/coole/syntax/Syntax**.
После него читается общесистемный
**{{pkgdatadir}}/syntax/Syntax**
для всех типов файлов, которые в нем не названы: файл пользователя хранит
только то, что пользователь добавил или хочет иначе, и его запись выигрывает у
установленной для файлов, к которым подходит.  Файлы из его строк
**include**
ищутся сначала в
*~/.local/share/coole/syntax/*,
а потом среди установленных.  Полная копия системного файла, какую делали
прежние версии, закрывает все типы файлов, установленные позже: оставьте в ней
только те записи, которые меняли.
Файл
**~/.local/share/coole/syntax/Syntax**
перечитывается при открытии каждого нового файла в редакторе. В нем лежат
правила подсветки, по одному в строке, и каждое говорит, какие слова каким
цветом подсвечивать.

Файл разбит на разделы, каждый из которых начинается со строки с командой
**file**.
Обычно разделы выносят в отдельные файлы командой
**include**.

У команды
**file**
три аргумента. Первый - регулярное выражение, которое проверяется на имени
файла и решает, относится ли раздел к этому файлу. Второй - описание типа
файла; оно используется в
**cooledit**,
а будущие версии
**coole**
тоже могут им воспользоваться. Третий, необязательный, - регулярное
выражение для первой строки текста файла. Правила раздела применяются, если
совпало имя файла или первая строка.

Раздел заканчивается там, где начинается следующий. Каждый раздел разбит на
контексты, а каждый контекст содержит правила. Контекст - это та область
текста, к которой относится определенный набор правил. Например, текст
внутри комментария C (между
**/\***
и
**\*/**)
имеет свой цвет. Это контекст, и правил внутри него нет, потому что внутри
комментария C подсвечивать, как правило, нечего.

Простейший раздел для программы на C выглядит так:

```
file .\*\\.c C\sProgram\sFile (#include|/\\\*)

wholechars abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_

# цвета по умолчанию
define  comment   brown
context default
  keyword  whole  if       yellow
  keyword  whole  else     yellow
  keyword  whole  for      yellow
  keyword  whole  while    yellow
  keyword  whole  do       yellow
  keyword  whole  switch   yellow
  keyword  whole  case     yellow
  keyword  whole  static   yellow
  keyword  whole  extern   yellow
  keyword         {        brightcyan
  keyword         }        brightcyan
  keyword         '*'      green

# комментарии C
context /\* \*/ comment

# директивы препроцессора C
context linestart # \n red
  keyword  \\\n  brightred

# строковые константы C
context " " green
  keyword  %d    brightgreen
  keyword  %s    brightgreen
  keyword  %c    brightgreen
  keyword  \\"   brightgreen
```

Каждый контекст начинается строкой вида:

**context**
[**exclusive**]
[**oneline**]
[**whole**|**wholeright**|**wholeleft**]
[**linestart**]
*разделитель*
[**linestart**]
*разделитель*
*[цвет текста]*
*[цвет фона]*
*[атрибуты]*

Первый контекст - исключение. Он должен начинаться командой

**context default**
*[цвет текста]*
*[цвет фона]*
*[атрибуты]*

иначе
**coole**
сообщит об ошибке. Параметр
**linestart**
требует, чтобы
*разделитель*
стоял в начале строки. Параметр
**whole**
требует, чтобы
*разделитель*
был целым словом. Чтобы слово начиналось на границе слова только слева, есть
параметр
**wholeleft**,
а чтобы оно так же заканчивалось справа -
**wholeright**.

Набор символов, из которых состоит целое слово, можно поменять в любом месте
файла командой
**wholechars**.
Левый и правый наборы задаются по отдельности:

**wholechars**
[**left**|**right**]
*символы*

Параметр
**exclusive**
подсвечивает текст между разделителями, но не сами разделители.

Параметр
**oneline**,
после
**exclusive**,
если заданы оба, заканчивает контекст в конце строки, если правого
разделителя на ней нет, так что незакрытый разделитель окрашивает не
больше, чем остаток своей строки.

Контекст может отдать текст между своими разделителями правилам другого
синтаксиса, если строкой ниже написать:

**embed**
[**soft**]
*тип*

где
*тип*
- имя правил так, как его называет строка file в файле Syntax, с \\s
вместо пробела.  Он ищется в файле Syntax, из которого читаются правила, а
затем в установленном вместе с coole, так что и копия файла Syntax старше
правил его находит; если типа нет ни там, ни там, контекст остаётся таким,
будто ничего не вкладывает, в своих собственных цветах.  Разделители остаются в цветах контекста.  Правый
разделитель заканчивает вложенный текст, где бы он ни встретился, в том
числе внутри строки или комментария вложенных правил.  Вложенный синтаксис
может в свою очередь вкладывать другой, на несколько уровней вглубь.
Например, HTML отдаёт скрипты правилам JavaScript:

```
  context <SCRIPT*> </SCRIPT> brightcyan
      embed JavaScript\sProgram
```

С
**soft**
правый разделитель заканчивает вложенный текст только вне строк,
комментариев и ключевых слов вложенных правил, так что в {{ "}}" }} шаблона
Jinja2 первые }} остаются частью строки, а в ${x/\\}/y} shell-скрипта первая
} остаётся частью экранирования.

Весь синтаксис может быть и слоем поверх другого, если среди его правил есть
строка

**overlay**
*тип*

Тогда его контексты окрашивают то, что в них, где бы оно ни стояло, а
остальной текст читают правила
*типа*,
которые видят содержимое контекстов пробелами и ничего о нем не знают.  Так
теги языка шаблонов окрашиваются и в тексте, и внутри HTML-тега, и в строке
атрибута, и в скрипте, а остальное окрашивает HTML.  Контекст по умолчанию у
слоя ничего не окрашивает: ключевое слово в нем лишь не дает начаться
контексту.  Тип, которого нет ни в одном файле Syntax, оставляет слой поверх
простого текста.  Например, Smarty поверх HTML:

```
  overlay HTML\sFile
  context default
      keyword {\s
  context {\* \*} brown
  context { } brightcyan
      embed soft Smarty\sTag
```

Каждое правило - это строка вида:

**keyword**
[**whole**|**wholeright**|**wholeleft**]
[**linestart**]
*строка цвет текста*
*[цвет фона]*
*[атрибуты]*

Строки контекстов и ключевых слов разбираются, поэтому табуляцию и пробел
можно записать как \t и \s. Перевод строки и обратная косая черта - это \n
и \\. Пробельные символы служат разделителями, поэтому как есть они не
годятся. Звездочку нужно писать как \\*, потому что сама \* - это шаблон,
который совпадает с любым числом символов. Например,

```
  keyword         '*'      green
```

красит все односимвольные константы C зеленым. Можно написать и

```
  keyword         "*"      green
```

для строковых констант, но такая строка не сможет переходить через перевод
строки. Шаблон можно использовать и в разделителях контекста, но не первым и
не последним символом.

Важна строка

```
  keyword  \\\n  brightgreen
```

Она задает ключевое слово из обратной косой черты и перевода строки.
Ключевые слова проверяются раньше разделителей контекста, поэтому оно не
дает контексту закончиться в конце строки, оканчивающейся обратной косой
чертой, и директива препроцессора C может продолжаться на нескольких
строках.

Возможные цвета: black, gray, red, brightred, green, brightgreen, brown,
yellow, blue, brightblue, magenta, brightmagenta, cyan, brightcyan,
lightgray и white. Особое слово "default" означает цвет терминала по
умолчанию. Другое особое слово, "base", означает основные цвета
редактора; оно удобно, когда нужно задать атрибуты, не меняя цвета фона.
Если доступны 256 цветов, их можно задать как color16 - color255, как
rgb000 - rgb555 или как gray0 - gray23.

Если файл синтаксиса общий с
**cooledit**,
цвета для
**coole**
и для
**cooledit**
можно задать по отдельности через косую черту:

```
keyword  #include  red/Orange
```

**coole**
берет цвет до косой черты. Цвета, которые понимает
**cooledit**,
описаны в cooledit(1).

Атрибуты - это bold, italic, underline, reverse и blink; если нужно
несколько, они соединяются знаком плюс.

Комментарий можно написать отдельной строкой, начав ее со знака решетки (#).

Для языка, в котором регистр не важен, в начале файла синтаксиса нужна
директива
**caseinsensitive**.

Из-за простоты реализации некоторые тонкости разбираются неверно, но это
мелкие неудобства. В целом же этими простыми правилами описывается довольно
широкий круг непростых случаев. Полезно заглянуть в файл синтаксиса и
посмотреть, что можно сделать с некоторой фантазией. Поддержки регулярных
выражений здесь нет и не будет: сделать ее невозможно.

Особый режим
**line-local**
предназначен для обычного текста. Он сбрасывается на каждом переводе строки
и на границе экрана и разбирает только показываемый текст. В нем есть
**number**
*макс цвет*
для десятичных чисел длиной до
*макс*
цифр,
**string**
*кавычка цвет*
для строк в одинарных или двойных кавычках и
**symbols**
*символы цвет*
для отдельно раскрашиваемых знаков препинания.

Полезный совет: работайте с тем, что можно сделать, а не пытайтесь сделать
то, с чем эта реализация не справится. И помните, что подсветка нужна не для
красоты кода, а для того, чтобы в нем было меньше ошибок.

Подсветку синтаксиса включает и выключает Ctrl-s.

# Цвета <a id="colors"></a>

coole пытается определить, поддерживает ли терминал цвет, по базе данных
терминалов и имени терминала. Иногда он ошибается, поэтому цветной режим
можно включить ключом -c или выключить ключом -b.

Если программа собрана с экранной библиотекой S-Lang, а не с ncurses, она
проверяет еще и переменную
**COLORTERM**:
если она задана, это действует так же, как ключ -c.

Терминалы, для которых цветной режим включается всегда, можно перечислить в
переменной
*color_terminals*
секции Colors ini-файла. Тогда coole не будет пытаться определить, есть ли у
терминала цвет. Пример:

```
[Colors]
color_terminals=linux,xterm
color_terminals=terminal-name1,terminal-name2...
```

Программа может быть собрана и с ncurses, и с S-Lang; ncurses не дает
способа принудительно включить цвет: она пользуется только сведениями из
базы данных терминалов.

# Скины <a id="skins"></a>

Цвета программы и линии ее рамок берутся из файла скина. Диалог
[Внешний вид](#appearance)
выбирает скин из списка.

Если в скине есть определения true color, в секции [skin] нужно задать ключ
'truecolors' со значением TRUE. Если true color не используется, а 256
цветов используются, нужно задать '256colors'.

Скином становится первый названный из:

```
1) ключ командной строки -S <скин>, --skin=<скин>
2) переменная окружения COOLE_SKIN
3) параметр skin секции [coole] ini-файла
4) скин с именем default
```

Имя может быть абсолютным путем к файлу скина (с расширением .ini или без
него). Иначе файл скина ищется в (до первого найденного):

```
1) ~/.local/share/coole/skins/
2) {{sysconfdir}}/coole/skins/
3) {{pkgdatadir}}/skins/
```

Формат файлов скинов описан в
**{{pkgdatadir}}/skins/README.txt**.
Цвета подсветки синтаксиса берутся из файлов синтаксиса, а не из скина;
смотрите
[Подсветка синтаксиса](#syntax-highlighting).

# Базы данных терминалов <a id="terminal-databases"></a>

coole позволяет поправить системную базу данных терминалов без прав root.
Диалог
[Распознавание клавиш](#learn-keys)
записывает выученное в
**~/.config/coole/term/\<TERM>**,
по строке на клавишу в секции
**[keys]**.
Кроме того, coole ищет в системном файле
**defaults.ini**
(в
**{{sysconfdir}}/coole**
или
**{{pkgdatadir}}**)
и в файле
**~/.config/coole/ini**
секцию "terminal:имя-вашего-терминала", а затем секцию "terminal:general".
Каждая строка секции содержит обозначение клавиши, знак равенства и
определение клавиши. Символ escape записывается как \\e, а control-x - как
^x. Строка
*copy=другой*
берет еще и все клавиши секции "terminal:другой".

Возможные обозначения клавиш:

```
f0 - f20      функциональные клавиши f0-f20
bs            backspace
home          клавиша home
end           клавиша end
up            стрелка вверх
down          стрелка вниз
left          стрелка влево
right         стрелка вправо
pgdn          page down
pgup          page up
insert        клавиша insert
delete        клавиша delete
complete      автодополнение
```

Например, чтобы клавиша insert означала Escape + [ + O + p, запишите в
ini-файл:

```
insert=\e[Op
```

Обозначение клавиши может включать модификаторы:

```
    ctrl-alt-right=\e[[1;6C
    ctrl-alt-left=\e[[1;6D
```

Это значит, что ctrl+alt+left посылает последовательность \\e[[1;6D, и
coole понимает "\\e[[1;6D" как Ctrl-Alt-Left.

Обозначение
*complete*
задает последовательности, которые вызывают автодополнение. Обычно оно
вызывается Alt-Tab, но ту же работу можно поручить и другим клавишам (на
клавиатурах, где много хороших неиспользуемых клавиш).

# Скрипты на Lua <a id="lua-scripting"></a>

Если coole собран с Lua, он выполняет Lua-скрипты, которые расширяют
редактор: действия, привязанные к клавишам и меню, реакции на события
редактора (файл открыт, записан, нажата клавиша), диалоги и полноэкранные
окна. Несколько команд редактора - такие скрипты: сортировка строк,
форматирование абзаца, вставка вывода команды, вставка символа по его коду,
вставка даты, декодирование base64 и рисование таблиц.

Каждый скрипт относится к рабочей области
**editor**.
Системные скрипты лежат в
**{{pkgdatadir}}/lua/scripts/editor/**,
а скрипты пользователя - в
**~/.local/share/coole/lua/scripts/editor/**,
по каталогу на скрипт, со своими
**lua.ini**
и
**init.lua**.
Диалог
[Lua-скрипты](#lua-scripts)
включает и выключает их.

Ключ
**--no-lua**
или переменная
**COOLE_NO_LUA**,
равная 1, запускают редактор без Lua-скриптов, а
*enabled=false*
в секции
**[Lua]**
ini-файла делает это насовсем.

Как написать скрипт и какие функции доступны скрипту, описано в
**LUA_PLUGINS.md**
и
**LUA_API_REFERENCE.md**,
которые устанавливаются вместе с документацией coole.

# Общие параметры <a id="general-settings"></a>

Эти параметры секции
**[coole]**
ini-файла относятся к программе, а не к редактору. Если не сказано иное, 1
включает параметр, а 0 выключает.

*auto_save_setup*
: Записывать настройки в ini-файл при каждом выходе из редактора.

*skin*
: Имя скина. Смотрите [Скины](#skins).

*shadows*
: Рисовать тень под диалогами и выпадающими меню.

*keymap*
: Файл раскладки. Смотрите [Переопределение клавиш](#keys_redefine).

*drop_menus*
: По F9 сразу открывать первое меню, а не только строку меню.

*mouse_close_dialog*
: Щелчок вне диалога закрывает его.

*mouse_repeat_rate, double_click_speed*
: Частота автоповтора кнопок мыши и время, в пределах которого два щелчка
считаются двойным, в миллисекундах.

*old_esc_mode, old_esc_mode_timeout*
: При включенном old_esc_mode одиночное нажатие Esc считается Esc через
old_esc_mode_timeout микросекунд, без ожидания следующей клавиши.

*show_all_if_ambiguous*
: При неоднозначном дополнении сразу показывать список вариантов. Смотрите
[Автодополнение](#completion).

*shell_patterns*
: Шаблоны условий меню пользователя - шаблоны оболочки (1) или регулярные
выражения (0).

*num_history_items_recorded*
: Сколько записей хранит каждая история строки ввода.

*confirm_history_cleanup*
: Спрашивать перед очисткой истории.

*clear_before_exec*
: Очищать экран перед выполнением команды меню пользователя.

*pause_after_run*
: Ждать нажатия клавиши после выполнения команды меню пользователя: никогда
(0), только на простых терминалах (1, по умолчанию) или всегда (2).

*alternate_plus_minus*
: Оставить клавишам плюс и минус цифровой клавиатуры значения плюса и минуса.

*verbose*
: Показывать ход долгих операций.

*keybar_visible*
: В секции
**[Layout]**:
показывать надписи функциональных клавиш внизу экрана.

# Параметры в ini-файле <a id="internal-file-editor-options"></a>

Большинство настроек задается в диалогах меню
**Настройки**,
а
**Сохранить настройки**
записывает их в секцию
**[coole]**
файла
**~/.config/coole/ini**.
Файл можно править и вручную; ниже перечислены имена, которые там носят
настройки редактора. Если не сказано иное, 1 включает параметр, а 0
выключает.

*editor_tab_spacing*
: Ширина символа табуляции. По умолчанию 8. Другое значение лучше не ставить,
потому что большинство других редакторов и программ просмотра считают
табуляцию равной 8. Для имитации меньшей табуляции есть
**editor_fake_half_tabs**.

*editor_fill_tabs_with_spaces*
: Никогда не вставлять символ табуляции, а заполнять пробелами (ascii 32) до
нужной позиции.

*editor_return_does_auto_indent*
: По Enter делать такой же отступ, как у первой строки выше, в которой есть
текст.

*editor_backspace_through_tabs*
: Одним нажатием Backspace удалять все пустое место до левого поля, если
между курсором и полем нет текста.

*editor_fake_half_tabs*
: Имитировать половинную табуляцию для тех, кто хочет программировать с
шириной табуляции 4, но не хочет менять ее с 8 (чтобы код выглядел так же и
в других программах). Между текстом и левым полем перемещение и табуляция
идут так, будто табуляция равна 4, а на деле для оптимального заполнения
используются пробелы и обычные табуляции. В других местах вставляется
обычная табуляция.

*editor_option_save_mode*
: Возможные значения 0, 1 и 2 - способ записи файла (смотрите и меню
настроек). Быстрое сохранение (0) сразу обрезает файл на диске до нулевой
длины и записывает в него содержимое редактора. Это быстро, но опасно:
системная ошибка во время записи оставит файл записанным частично, и данные
могут пропасть. Безопасное сохранение (1) сначала записывает содержимое во
временный файл; при сбое исходный файл не трогается, а когда временный файл
записан успешно, он переименовывается в имя исходного и заменяет его. Самый
надежный способ - резервные копии (2): перед изменениями создается
резервная копия файла. Расширение резервной копии задается в диалоге.
Учтите, что две записи подряд заменят и резервную копию, и исходный файл.

*editor_word_wrap_line_length*
: Длина строки для переноса. По умолчанию 72.

*editor_backup_extension*
: Что добавляется к имени резервной копии. По умолчанию "~".

*editor_line_state*
: Показывать колонку состояния строк. Сейчас в ней номер строки и отметки
сверток и скрытых участков. Переключается клавишей Alt-n.

*editor_visible_spaces*
: Показывать пробелы в конце строк. При editor_visible_spaces=1 они
показываются как '.'.

*editor_visible_tabs*
: Показывать табуляции. При editor_visible_tabs=1 табуляции показываются как
'<---->'.

*editor_show_control_chars*
: Показывать управляющие символы в виде '^M' или '^L'. При
editor_show_control_chars=0 каждый из них занимает одну пустую клетку.
Переключается пунктом "Управляющие символы" меню "Команда".

*editor_persistent_selections*
: Не снимать выделение блока после перемещения курсора.

*editor_drop_selection_on_copy*
: Снимать выделение после копирования в файл обмена.

*editor_cursor_beyond_eol*
: Разрешить курсору стоять за концом строки.

*editor_cursor_after_inserted_block*
: Ставить курсор после вставленного блока.

*editor_syntax_highlighting*
: Включить подсветку синтаксиса.

*editor_edit_confirm_save*
: Спрашивать подтверждение при записи.

*editor_option_typewriter_wrap*
: Разрывать строку по
**editor_word_wrap_line_length**
прямо при наборе, как пишущая машинка. Один из трех режимов переноса
диалога настроек.

*editor_option_auto_para_formatting*
: Форматировать абзац, в котором стоит курсор, при наборе. Другой из трех
режимов переноса; выключенный перенос означает, что строки не переносятся
вовсе.

*editor_option_save_position*
: Запоминать позицию в файле при выходе.

*editor_group_undo*
: Объединять при отмене несколько однотипных действий (вставку и замену,
удаление, перемещение, набор).

*editor_wordcompletion_collect_entire_file*
: Искать варианты автодополнения во всем файле (1) или только от начала
файла до курсора (0).

*editor_wordcompletion_collect_all_files*
: Искать варианты автодополнения во всех загруженных файлах (1, по
умолчанию), а не только в редактируемом (0).

*editor_stop_format_chars*
: Символы, останавливающие форматирование абзаца. Если строка начинается с
одного из них, она и все следующие строки абзаца не трогаются. По умолчанию
"**-+\*\\,.;:&>**".

*editor_state_full_filename*
: Показывать полный путь в строке состояния. Если выключено (по умолчанию),
показывается только имя файла.

*editor_filesize_threshold*
: Размер, больше которого файл открывается только после вопроса. Значение
принимает суффикс, например 64M или 512K. По умолчанию 64M.

*editor_show_right_margin*
: Отмечать колонку
**editor_word_wrap_line_length**
как правое поле. Переключается пунктом "Правое поле" меню "Команда". По
умолчанию выключено.

*editor_simple_statusbar*
: Показывать более короткую строку состояния, без смещения и символа под
курсором. По умолчанию выключено.

*editor_check_new_line*
: При записи спрашивать о недостающем переводе строки в конце файла.
Переключается флажком "Проверять перевод строки POSIX" диалога режима
сохранения. По умолчанию выключено.

# ОКРУЖЕНИЕ <a id="environment"></a>

Ниже перечислены переменные, которые читает coole. Переменные вроде
**TERM**, **SHELL**, **HOME** или **PATH** здесь не перечислены: программа
читает их, чтобы узнать, где она работает, а не для настройки.

**COOLE_DATADIR**
: Каталог, из которого берутся файлы данных, вместо {{pkgdatadir}}. Смотрите
[ФАЙЛЫ](#files).

**COOLE_PROFILE_ROOT**
: Корень файлов пользователя, абсолютным путем, вместо домашнего каталога.
Смотрите [ФАЙЛЫ](#files).

**COOLE_SKIN**
: Скин, по имени или по пути. Смотрите [Скины](#skins).

**COOLE_KEYMAP**
: Файл раскладки. Смотрите [Переопределение клавиш](#keys_redefine).

**COOLE_TMPDIR**, **TMPDIR**
: Каталог для временных файлов программы - первая заданная из двух; если не
задана ни одна, /tmp.

**COOLE_NO_LUA**
: Значение 1 запускает программу без среды Lua. Ни один Lua-скрипт не
загружается.

**KEYBOARD_KEY_TIMEOUT_US**
: Сколько ждать продолжения управляющей последовательности, в микросекундах.

**COLORTERM**
: Читается при выборе цветов. Смотрите [Цвета](#colors).

**COOLE_LOG_ENABLE**, **COOLE_LOG_FILE**
: Отладочный журнал пишется, когда COOLE_LOG_ENABLE равна 1. Без
**COOLE_LOG_FILE** используется файл, заданный параметром *logfile* секции
*[Logging]* ini-файла, а без него - *~/.cache/coole/coole.log*.

**COOLE_SPELL_LOG**
: Файл, в который проверка правописания пишет отладочный журнал. Своего
выключателя у нее нет: журнал пишется, когда переменная называет файл.

# ФАЙЛЫ <a id="files"></a>

Полные пути, приведенные ниже, в разных установках могут отличаться. На
файлы данных влияет еще и переменная окружения
**COOLE_DATADIR**:
если она задана, ее значение используется в путях ниже вместо
{{pkgdatadir}}. Файлы пользователя следуют каталогам XDG:
*~/.config*,
*~/.local/share*
и
*~/.cache*
означают
**XDG_CONFIG_HOME**,
**XDG_DATA_HOME**
и
**XDG_CACHE_HOME**,
если они заданы.

*{{pkgdatadir}}/help/coole.md*
: Файл помощи программы (переводы - coole.ru.md и т. д.); рядом лежат
файлы помощи плагинов редактора.

*{{sysconfdir}}/coole/coole.ini*, *{{pkgdatadir}}/coole.ini*
: Общесистемные файлы настроек; используются, только если у пользователя нет
своего файла
**~/.config/coole/ini**.
Если есть {{sysconfdir}}/coole/coole.ini, {{pkgdatadir}}/coole.ini не
используется.

*{{sysconfdir}}/coole/defaults.ini*, *{{pkgdatadir}}/defaults.ini*
: Общие настройки, которые действуют на всех пользователей, независимо от
того, есть у них ~/.config/coole/ini или нет. Сейчас из него загружаются
только
[настройки терминалов](#terminal-databases).

*{{sysconfdir}}/coole/keymap.ini*, *{{pkgdatadir}}/keymap.ini*
: Общесистемные привязки клавиш. Смотрите
[Переопределение клавиш](#keys_redefine).

*{{sysconfdir}}/coole/coole.menu*, *{{pkgdatadir}}/coole.menu*
: Общесистемное [меню пользователя](#edit-menu-file).

*{{sysconfdir}}/coole/spell.keymap, ctags.keymap*
: Клавиши плагинов проверки правописания и ctags; одноименный файл в
~/.config/coole переопределяет их.

*{{pkgdatadir}}/syntax/\**
: Общесистемные файлы синтаксиса; используются, только если у пользователя
нет своего такого файла в
**~/.local/share/coole/syntax/**.

*{{pkgdatadir}}/skins/\**
: Скины, которые поставляются с программой.

*{{pkgdatadir}}/charsets*
: Список кодовых страниц.

*{{pkgdatadir}}/lua/scripts/editor/\**
: Lua-скрипты, которые поставляются с программой.

*{{pkgdatadir}}/examples/macros.d/\**
: Примеры скриптов для макросов.

*{{editor_plugins_dir}}/*
: Плагины редактора, загружаемые при работе.

*~/.config/coole/ini*
: Собственные настройки пользователя. Если этот файл есть, настройки
читаются из него, а не из общесистемного файла.

*~/.config/coole/keymap.ini*
: Собственные привязки клавиш пользователя.

*~/.config/coole/menu*
: Собственное [меню пользователя](#edit-menu-file).

*~/.config/coole/plugins.ini*
: Выключенные плагины и Lua-скрипты.

*~/.config/coole/term/\<TERM>*
: Клавиши, выученные в диалоге [Распознавание клавиш](#learn-keys).

*./.coole.menu*
: Меню пользователя текущего каталога. Если этот файл есть в текущем
каталоге, он используется вместо меню пользователя и общесистемного меню.

*~/.local/share/coole/history*
: Истории строк ввода.

*~/.local/share/coole/filepos*
: Места, на которых были оставлены файлы, для
*editor_option_save_position*.

*~/.local/share/coole/clipboard*
: Файл обмена редактора.

*~/.local/share/coole/macros*
: Записанные [макросы](#macros).

*~/.local/share/coole/macros.d/macro.N.sh*
: Скрипты оболочки для макросов.

*~/.local/share/coole/syntax/Syntax*
: Собственный файл синтаксиса пользователя.

*~/.local/share/coole/skins/*
: Собственные скины пользователя.

*~/.local/share/coole/lua/scripts/editor/*
: Собственные Lua-скрипты пользователя.

*~/.cache/coole/block*
: Файл блока, с которым работают меню пользователя и скрипты макросов.

*~/.cache/coole/temp*
: Временный файл редактора.

Корневой каталог файлов пользователя можно поменять переменной окружения
**COOLE_PROFILE_ROOT**.
Ее значение должно быть абсолютным путем. Если COOLE_PROFILE_ROOT не задана
или пуста, используется переменная HOME. Если не задана или пуста и HOME,
каталоги берутся у библиотеки GLib.
