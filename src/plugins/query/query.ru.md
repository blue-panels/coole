# Query <!-- help:notitle -->

**Плагин запросов редактора**

Выполняет запросы файла в базе данных и показывает ответ внизу экрана: что
сказала база и документы или строки по столбцам. MongoDB выполняет *mongosh*,
её оболочка; PostgreSQL - *libpq*, её клиентская библиотека, как рассказано в
части **PostgreSQL** в конце. Работает только в *coole -Q*. Какая база,
говорит *MC_QUERY_KIND*, *mongo* или *postgres*; без неё *MC_MONGO_URI*
означает MongoDB, а файл *.sql* - PostgreSQL. Если файл не указан, файл
запросов - файл базы данных, *~/.local/share/coole/queries/* с именем
*MC_MONGO_DB* и *.js*: запросы базы остаются до следующего раза.

**Что нужно**

*mongosh*
: Оболочка MongoDB, которая выполняет запросы: пакет mongodb-mongosh из
репозитория MongoDB или его архив.

*mongolsp*
: Языковой сервер запросов, для их дополнения; без него запросы выполняются
так же. Пакет *mongolsp* из его выпусков,
<https://github.com/blue-panels/mongolsp/releases>, ставится через apt, или
*install.sh* из его архива, с Node.js 18 или новее. Первые строки вкладки
Вывод говорят, найдены ли оба.

**К чему подключается**

mongosh узнаёт это из окружения coole, которое наследует; coole из него
читает только имя сервера для заголовка вывода:

*MC_MONGO_URI*
: Строка подключения, *mongodb://user:password@host:port/?options*. В
командной строке она не передаётся: там её мог бы прочитать любой
пользователь.

*MC_MONGO_DB*
: База данных; без неё - база из строки подключения.

*MC_MONGOSH*
: Программа; без неё - *mongosh* из PATH.

Строка *use("name")* выполняет запросы после неё в этой базе, как
*db = db.getSiblingDB("name")*, в том числе часть между строками *// ---* или
выделение, выполненные отдельно, и заголовок вкладки Вывод говорит об этом:
mongosh без своей базы не принимает *use()*, а языковой сервер запросов,
*mongolsp* из lsp.json, по ней знает базу, коллекции которой дополняет. Файл
без такой строки получает при запуске -Q в начало *use("name")* с
*MC_MONGO_DB* или с базой из строки подключения; файл меняется, сохранять его
или нет - решать вам, и Вывод об этом говорит. С сервером в PATH Ctrl-Space и
точка после *db* дополняют коллекции, их поля, методы, стадии и операторы.

Сам запрос передаётся mongosh в командной строке, которую любой пользователь
может прочитать, пока он выполняется: секрет, нужный запросу, токен или
пароль, лучше брать из окружения, *process.env.NAME*, которое mongosh тоже
наследует.

**Клавиши**

Это клавиши по умолчанию; их можно изменить в **Настройки -> Привязки
клавиш -> Редактор -> Query** или в секции *[query]* раскладки клавиш.

**F5**
: Выполнить выделение, иначе часть файла между строками *// ---*, в которой
стоит курсор, иначе весь файл. Скрипт выполняется целиком, его строки
пользуются тем, что сделали строки до них, есть между ними пустые строки или
нет; в файле многих запросов перед каждым стоит строка *// ---*, слова после
черточек при надобности называют его. Разделитель открывает часть после себя.

**Ctrl-F5**
: Выполнить весь файл, даже при выделении или разделителях.

```
// --- the last orders
// @table
db.orders.find({ status: 1 })
  .sort({ ts: -1 })
  .limit(20)

// --- how many
db.orders.countDocuments({ status: 1 })
```

**F5** во время выполнения запроса спрашивает, остановить ли его.

Строка *// @limit 20* в запросе ограничивает его документы, без числа - до
100: цепочка *find()* получает *.limit(20)* строкой после себя, если у неё нет
своего *.limit()*, а *aggregate([...])* - стадию *{ $limit: 20 }* в конце
конвейера, если в нём нет своего *$limit*, а также *$out* или *$merge*, после
которых стадий быть не может. Заголовок вкладки Вывод говорит, какой предел
поставлен или что ограничивать в запросе нечего. Файл остаётся как есть.

**Вкладки**

*Вывод*
: То, что напечатал mongosh, как он это печатает: *ObjectId('...')*,
*ISODate('...')*, курсор до 1000-го документа. Первая строка говорит строки
запроса, время выполнения, сервер и код возврата; ошибка красная.
Синтаксическая ошибка помечает свою строку в файле, и курсор переходит туда.

*Таблица*
: Таблица каждого массива или курсора, напечатанного *printjson()* или
*print()*, по порядку, с номерами, есть в запросе строка *// @table* или нет;
Вывод показывает напечатанное как есть. Курсор читается в массив своих
документов. Таблица в Markdown, столбцы выровнены: столбец на каждый ключ
документов, *_id* первым; у документа без этого ключа ячейка пуста; объект
или массив внутри показан так, как его показывает mongosh,
*{ClientUuid: "hashed"}*, *[1, 2, 3]*; *|* в значении - *\|*; значение длиннее
40 столбцов обрезается; показаны первые 100 документов массива, посчитаны
все. Вкладка выходит вперёд, когда документы есть. Число или одиночный
документ остаются во вкладке Вывод.

Запрос со строкой *// @table* получает и таблицу значения, которым он
кончается, последнего: он выполняется с *--json=relaxed*, и Вывод показывает
это значение как JSON. Запросу, который кончается цепочкой *find()* или
*aggregate()*, её *.sort()*, *.limit()* и подобными, строкой после неё
добавляется *.toArray()*.

*История*
: Версии файла запросов впереди, его имя в заголовке вкладки, новые первыми,
по строке на версию: время версии, сколько раз она выполнялась и чем кончился
последний запуск, сколько строк добавлено и убрано с прошлой версии, первая
строка последнего выполненного ею запроса. Каждый запуск сохраняет файл,
сохранённый или нет, как версию, если он не такой же, как при прошлом
запуске: тогда ещё один запуск считается в её строке. Версии лежат в данных
пользователя, *~/.local/share/coole/queries/.history/*, по каталогу на файл,
версия названа своим временем, *20261024-173750.js*; хранятся 200 новейших.
Строка курсора выбирает версию:

**Enter**, двойной щелчок
: Файл запросов, каким он был при том запуске: его текст становится текстом
версии, в своём окне, одним изменением, которое отменяет **Undo**, курсор на
запросе. Прежнее содержимое, если оно ещё не версия, как при переходе от
версии к версии, сначала сохраняется одной строкой *текущая* вместо прежней,
которая так и не выполнялась: **Enter** на ней возвращает прежнюю работу.
Версии - хранилище: они не открываются, и файл хранилища при запуске версий
не получает.

**F3**
: Что изменилось в файле с этой версии, *diff -u*, во вкладке Вывод.

**F5**
: Снова выполнить последний запрос версии как он был, файл остаётся как есть;
его ошибки в файле не помечаются.

Текст, отмеченный в Истории, копируется **Ctrl-Ins**: Enter и F3 там -
клавиши списка. Другой файл впереди показывает свою Историю.

**Ctrl-Alt-PgDn** и **Ctrl-Alt-PgUp** переходят с вкладки на вкладку.

**Ctrl-Alt-S**
: Окно Схема справа, QuerySchema, как для PostgreSQL ниже: базы данных, база
подключения первой и раскрытой, *admin*, *local* и *config* пропущены, если
это не одна из них; их Коллекции с числом документов, которое считает сервер,
*~1200*, Представления, *на orders*, и Временные ряды. Раскрытая коллекция
читается тогда же: её Поля по выборке из 100 документов, никогда не значения,
с типами и, если поле есть не у всех, долей тех, у кого есть, *50%*; её
Индексы и их ключи, *unique*, *sparse*, *ttl*; её Валидатор, Конвейер
представления. Enter сворачивает и раскрывает, F5 кладёт первые 100
документов коллекции во вкладку Таблица, F3 вставляет их запрос в файл
запросов, *// @table* и
*db.getSiblingDB("shop").getCollection("orders").find({}, { _id: 1, total:
1 }).limit(100)*, в её базе, какой бы ни был *use()* файла, только по полю
строки, если это поле, Insert вставляет *db.orders*, поле, ключ индекса. F4
вставляет туда DDL коллекции, как F3 - её запрос: её *drop()*,
закомментированный, её *createCollection()* с параметрами, валидатором,
*capped*, временным рядом, или *createView()* представления, и
*createIndex()* для каждого индекса, кроме *_id_*; для базы данных - её
*dropDatabase()*, закомментированный, и её *use()*. Значение с типом BSON,
дата, Long, помещается в *EJSON.deserialize()*; индексы, которые не удалось
прочитать, указаны в комментарии. Это определение, а не резервная копия:
пользователей, ролей и документов в нём нет; документ, ключ которого - ключ
Extended JSON, *{ $date: "..." }*, читается обратно как этот тип, а Double
без дробной части - как число: mongosh эти типы уже потерял. Схему читает
mongosh, каждый раз отдельным запуском: запрос, который создаёт или удаляет
коллекцию, представление или индекс или вставляет документы, перечитывает её.

**Запрос, написанный ИИ**

**F6**
: Запрос по просьбе, записанной в файле, пишет ИИ: просьба - абзац под
курсором, его строки между пустыми строками, или выделение, словами
пользователя, *заказы за последнюю неделю по пользователям*. Программа ИИ
пишет запрос, он вставляется под просьбой, а просьба становится комментарием,
*//* или *--*: одно изменение, которое отменяет Undo. Запрос не выполняется:
его выполняет F5. **F6** на просьбе, которая стала комментарием над
запросом, пишет его заново на месте того запроса. Абзац с запросом
пользователя и словами, *посчитай среднее ttl* под *find()*, весь является
просьбой: ИИ пишет запрос, о котором просят слова, исходя из того, только
слова становятся комментарием, а запрос ИИ идёт после абзаца через пустую
строку, запрос пользователя остаётся как есть. *// @table* и *// @limit*
относятся к запросу и никогда не являются словами просьбы. Ответ без запроса,
вопрос ИИ, оставляет файл как есть и показывается во вкладке Вывод. **F6**,
пока ИИ пишет, спрашивает, остановить ли его. Вывод говорит, сколько это
заняло, и что ИИ сказал помимо запроса.

ИИ сообщаются имена в базе данных, никогда не строки: для MongoDB -
коллекции, поля выборки документов каждой с типами, их индексы и
представления, в базе *use()* над просьбой; для PostgreSQL - отношения её
схем, их столбцы с типами и ключами, схема *MC_PG_SCHEMA* первой; при
*MC_QUERY_READ_ONLY=1* - что ничего менять нельзя.

*MC_QUERY_AI*
: Программа ИИ, иначе ключ *ai* секции *[Query]* файла *~/.config/coole/ini*;
окружение выбирает для запуска другую, чем в настройках:

```
[Query]
ai=codex
```

*claude*, если не задано ни то ни другое, запускается как *claude -p --tools ""
--no-session-persistence*, *codex* - как *codex exec --skip-git-repo-check
--ephemeral --sandbox read-only --color never -*: просьба на stdin, их
инструменты не запускаются. Другое значение - командная строка, которая
запускается как есть, читает просьбу на stdin и печатает запрос, в блоке кода
Markdown или сам по себе. Она запускается в каталоге временных файлов, без
*PGPASSWORD* и *MC_MONGO_URI* в окружении. Первые строки вкладки Вывод
говорят, найдена ли она.

Скрипты, которыми плагин читает схему и то, что сообщается ИИ, и тот, что
mongosh выполняет перед каждым запросом, - файлы */usr/share/coole/query*:
*mongo-list.js*, *mongo-details.js*, *mongo-ai.js*, *mongo-ddl.js*,
*mongo-prefix.js*, *pg-list.sql*, *pg-details.sql*, *pg-ai.sql*,
*pg-ddl-relation.sql*, *pg-ddl-function.sql*. Одноимённый файл в
*~/.config/coole/query* или в */etc/coole/query* выполняется вместо него. В
них *{{> name}}* - часть *name* с тем же расширением, читаемая из тех же
каталогов, *{{name}}* - значение, которое подставляет плагин: база данных,
коллекция, oid; строка, которая только комментарий, пропускается. Если
какого-то нет, об этом говорят Вывод или Схема.

Узел Схемы имеет перед именем знак того, что он такое, если его даёт скин в
своей секции *[query]*; по умолчанию знаков нет:

```
[query]
    schema-char = ◫
    table-char = ▦
    column-char = ·
```

Ключи: *schema-char*, *database-char*, *table-char*, *partitioned-char*,
*view-char*, *matview-char*, *foreign-char*, *sequence-char*,
*function-char*, *procedure-char*, *aggregate-char*, *column-char*,
*key-char*, *fkey-char*, *index-char*, *reference-char*, *trigger-char*,
*collection-char*, *timeseries-char*, *field-char*, *validator-char*,
*pipeline-char*.

Знак имеет цвет того, что такое узел: ключ знака без *-char*, цвет скина
на фоне редактора; имя - цвета текста. *item* - цвет имени элемента:
столбца, ключа, индекса, поля; *info* - того, что стоит справа в строке; по
умолчанию цветов нет:

```
[query]
    table = cyan
    view = green
    item = gray
    info = gray
```

**PostgreSQL**

*coole -Q* с *MC_QUERY_KIND=postgres* или с файлом *.sql* выполняет запросы в
PostgreSQL. Пока он работает, он держит одно подключение: транзакция,
временные таблицы и то, что задал *SET*, остаются от одного F5 до другого.

*libpq5*
: Клиентская библиотека PostgreSQL. coole загружает её при запуске -Q и
нуждается в ней только для PostgreSQL; libpq 17 и новее отдаёт строки
порциями и имеет свою отмену, более старая отдаёт их по одной.

*postgres-language-server*
: Языковой сервер SQL, для дополнения таблиц и столбцов, подсказок и ошибок
по мере набора; без него запросы выполняются так же. Его выпуски на
<https://github.com/supabase-community/postgres-language-server/releases>.
Первые строки вкладки Вывод говорят, найдены ли оба.

libpq берёт, к чему подключаться, из окружения, как *psql*: *PGHOST*,
*PGPORT*, *PGUSER*, *PGDATABASE*, *PGSERVICE* и *~/.pg_service.conf*,
*PGSSLMODE*. Пароль лучше держать в *~/.pgpass*, который читают libpq и
языковой сервер, чем в *PGPASSWORD*. coole добавляет к подключению его
кодировку, UTF8, а при *MC_QUERY_READ_ONLY=1* - транзакции, которые ничего не
пишут, *[RO]* в заголовке: это защита от промаха, а не право, *SET* её
снимает; что можно писать, решает роль.

Если файл не указан, файл запросов -
*~/.local/share/coole/queries/postgres/*, имя подключения,
*MC_PG_CONNECTION* или *PGSERVICE*, и имя базы данных с *.sql*.

С *MC_PG_RELATION*, таблицей или представлением, и *MC_PG_SCHEMA*, её схемой,
как coole запускает панель PostgreSQL, после подключения выполняется *SELECT*
первых 100 строк, файл остаётся как есть; пустой файл получает этот запрос,
изменённым, не сохранённым.

**F5**
: Выполнить выделение, иначе весь файл, как есть, одним запросом: его команды
составляют одну транзакцию, если в нём нет своего *BEGIN*; ошибка отменяет те, что
были до неё, а остальные не выполняются. *CREATE DATABASE*, *VACUUM* и
подобные не принимают с собой других команд: выделите их отдельно. Команды
psql, *\d*, *\copy*, к PostgreSQL не относятся.

**Ctrl-F5**
: Выполнить весь файл, даже при выделении.

**F5** во время выполнения запроса спрашивает, остановить ли его: серверу
посылается просьба его отменить, и Вывод говорит, чем он кончился. Так же
останавливается и подключение, которое не устанавливается.

*Вывод*
: Первая строка говорит строки запроса, время выполнения, сервер, чем он
кончился и состояние транзакции: *[TX]*, пока она открыта,
*[СБОЙ ТРАНЗАКЦИИ: нужен ROLLBACK]*, когда её команда не удалась и сервер не
принимает других запросов до *ROLLBACK*; это говорит и заголовок вкладки.
Затем - что сделала каждая команда, *SELECT 12*, *UPDATE 4*, между ними
уведомления сервера, иногда уведомление перед командой, за которой оно
следует; ошибка с кодом, *ERROR [23505]*, её *DETAIL* и *HINT*, её строка
помечена в файле, и курсор там. *COPY ... TO STDOUT* печатает свои строки
здесь; *COPY ... FROM STDIN* завершается, так как coole нечего отправить.

*Таблица*
: Таблица строк каждой команды, у которой они есть, *SELECT* и
*... RETURNING*, с номерами: первые 100 строк, посчитаны все, памяти столько
же и для миллионов. *NULL* так и показан, *bytea* - длиной и началом, длинное
значение - началом. Строки команды, которая не удалась после них, отмечены
как неполные.

*История*
: Как для MongoDB; запуск говорит, чем он кончился, *SELECT 12* или
*ERROR 42P01*, а его версии - *.sql*.

**QueryRollback**
: Выполнить *ROLLBACK*. Своей клавиши нет: её назначают в
*~/.config/coole/keymap.ini*, секция *[query]*.

**Ctrl-Alt-S**
: Окно Схема справа, QuerySchema: показывается, если его нет, получает фокус,
если у него его нет, и прячется, если фокус у него. Показывается после
подключения: схемы базы данных, схема *MC_PG_SCHEMA* первой и раскрытой,
иначе *public*, системные пропущены. У схемы есть группы, в которых что-то
есть: Таблицы, Представления, Материализованные представления, Внешние
таблицы, Последовательности, Функции, объекты расширений пропущены. Таблица
показывает число строк по оценке сервера, *~50k*; секционированная таблица -
свои секции под собой, в разделе Секции.

Раскрытое отношение имеет разделы, которые читаются тогда же: Столбцы, их
типы, *not null*, значение по умолчанию, *identity*, *generated*; Ключи,
первичный и уникальные; Внешние ключи; Индексы; Ссылки, внешние ключи других
таблиц на него; Триггеры. У таблицы есть все, и пустые тоже, у представления
и подобных - те, в которых что-то есть.

В Схеме дерево; линейка кнопок показывает F3, F4 и F5:

**Up**, **Down**, **PgUp**, **PgDn**, **Home**, **End**
: Перемещение по узлам.

**Enter**
: Свернуть или раскрыть узел: схему, группу, отношение, раздел. Так же
действует двойной щелчок; **Right** раскрывает, **Left** сворачивает или
переходит к родителю. Раскрытое и ещё не прочитанное отношение показывает
*...*, пока не придут его разделы.

**F10**, **Esc**
: Закрыть окно; Ctrl-Alt-S создаёт его снова.

**F5**
: Первые 100 строк отношения узла или того, к которому он относится, во
вкладке Таблица: запрос без файла, QuerySchemaRows, его текст вверху Таблицы
и в заголовке Вывода.

**F3**
: Запрос строк отношения вставляется в файл запросов, столбцы по одному в
строке, только столбец узла, если узел - столбец; столбцы сначала читаются,
если их ещё нет: *SELECT id, name FROM public.users LIMIT 100;*, в файл, где
нажата F3, на строку курсора, если она пуста, отдельным абзацем, иначе после
её абзаца; курсор переходит туда, F5 выполняет его. Запрос, который ждёт
своих столбцов, больше не вставляется, если Схема перечитывается или нажата
другая F3; Вывод говорит об этом, а также о том, что столбцы не удалось
прочитать. QuerySchemaQuery.

**F4**
: DDL отношения узла, функции, схемы вставляется в файл запросов, как F3
вставляет запрос, QuerySchemaDdl: его *DROP*, закомментированный, затем его
*CREATE*. У таблицы - столбцы с типами, значениями по умолчанию, identity,
generated и *NOT NULL*, её ограничения, *PARTITION BY* или *PARTITION OF*,
затем её индексы, не принадлежащие ограничениям, её триггеры и комментарии; у
представления - его запрос, у внешней таблицы - сервер и параметры, у
последовательности - её числа, закомментированные, если она принадлежит
столбцу identity, у функции - определение, которое даёт PostgreSQL. Имена в
нём со схемой, *public.users*, каким бы ни был путь поиска. То, что CREATE
потерял бы, идёт после него: ограничения *NOT VALID*, значения по умолчанию
столбцов представления, значения, которые таблица или секция задаёт
унаследованному, режим триггера. Это определение, а не *pg_dump*: владельца,
прав, защиты на уровне строк и её политик, табличного пространства, строк и
значения последовательности в нём нет.

**Insert**
: Вставить у курсора файла запросов то, что называет узел, так, как это
принимает SQL, QuerySchemaInsert: *sales."Orders"* для отношения, имя схемы,
столбца, индекса, триггера; столбцы ключа, все столбцы узла Столбцы; таблицу
ссылки; *sales.total(* для функции.

**QuerySchemaRefresh**
: Перечитать схемы, без своей клавиши; раскрытое и узел курсора остаются
такими же. Схемы перечитываются и сами после запроса, чей *CREATE*, *ALTER*
или *DROP* зафиксирован.

Схема читает каталог своим подключением, из того же окружения, только для
чтения, как и основное: выполняющийся запрос или сбойная транзакция не мешают
её читать, и она видит только зафиксированное.

Подключение, потерянное во время запроса, так и отмечается, а транзакция,
временные таблицы и *SET* сеанса теряются вместе с ним; F5 подключается снова
и ещё раз говорит об этом.

У языкового сервера своё подключение: он знает таблицы базы данных, но не
временные таблицы сеанса F5 и не схему, которую *SET search_path* поставил
впереди; *MC_PG_SCHEMA* - схема, которую он знает первой, иначе *public*. Он
не выполняет команд: запросы выполняет только F5.
