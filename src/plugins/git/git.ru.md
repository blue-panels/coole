# Git <!-- help:notitle -->

**Плагин git редактора**

Показывает изменения рабочего дерева git, в котором лежит файл, и коммиты
его ветки, как это делает gitui, и дает написать сообщение коммита в окне
редактора: нового коммита, исправленного последнего (amend) или любого
коммита ветки, которому дается другое сообщение (reword).

Рабочее дерево - это дерево файла на переднем плане, иначе дерево проекта,
иначе дерево текущего каталога. Плагин запускает *git* системы, поэтому
действуют хуки, настройки и имя пользователя.

**Окно Git**

**Alt-Shift-C** открывает его на вкладке **Status**, **Alt-Shift-L** - на
вкладке **Log**. В меню **Окна** есть пункт для каждого его окна: **Git:
commit message**, **Git: status and log**, **Git: staged changes** и **Git:
diff**; пункт открывает окно Git, если оно закрыто, и передает клавиши своему
окну. Окна стоят рамка к рамке там, где стоят окна файлов:

```
 ┌─[COOLE_EDITMSG]────────────────────┐┌─[Diff]────────────────┐
 │ сообщение                          ││ дифф файла            │
 │ следующего коммита                 ││ или коммита           │
 └────────────────────────────────────┘│                       │
 ╔═[ 1 Status ] [ 2 Log ] [ 3 Graph ]═╗│                       │
 ║ неиндексированные изменения        ║│                       │
 ╚════════════════════════════════════╝│                       │
 ┌─[Staged changes]───────────────────┐│                       │
 │ индексированные изменения          ││                       │
 └────────────────────────────────────┘└───────────────────────┘
```

Слева - сообщение следующего коммита, на треть высоты; под ним изменения,
не добавленные в индекс, с вкладками и веткой в заголовке и с тем, насколько
ветка впереди своей upstream-ветки и позади нее; внизу изменения в индексе.
Справа - дифф того, на чем стоит курсор. У списков и диффа полосы прокрутки
на рамках. При включенных липких окнах (**Окна -> Переключить липкие окна**)
окна меняют размер вместе; каждое можно развернуть на весь экран. Закрытие
одного из них, кнопкой его рамки или **Файл -> Закрыть**, убирает его с
экрана, а остальные занимают его место; пункт в меню **Окна** возвращает
его. Закрытие последнего, или **Esc** и **F10** в любом из них, закрывает
окно Git, а сообщение остается до следующего раза.

**1**, **2**, **3**
: Вкладки Status, Log и Graph; щелчок по вкладке в заголовке делает то же.

**Tab**
: Клавиши переходят к следующему окну: изменения, изменения в индексе,
дифф.

**Right**, **Left**
: В дифф и обратно. В диффе они прокручивают его вбок; Up, Down, PgUp, PgDn,
Home, End и Space прокручивают его.

**F5**, **Ctrl-R**
: Перечитать все. Статус перечитывается и сам, когда окно выходит на
передний план.

**F6**, **F7**, **Shift-F5**
: *git push*, *git pull*, *git fetch*, набранные в оболочке окна терминала
(Ctrl-o), которое появляется внизу и получает клавиши, чтобы git мог
спросить там пароль. Когда git закончит, все перечитывается, и клавиши
возвращаются окну Git; если git отказал, они остаются у его ответа. Без
плагина terminal git запускается на терминале редактора, а редактор
убирается с экрана до нажатия клавиши.

**F6** сначала спрашивает: показывает ветку и насколько она впереди своей
upstream-ветки и позади нее, удаленный репозиторий, куда отправлять, - выбран
тот, куда отправил бы git (*branch.<имя>.pushRemote*, *remote.pushDefault*,
удаленный репозиторий upstream-ветки, *origin*), и три флажка. Push называет
удаленный репозиторий и ветку: ветку upstream в ее удаленном репозитории,
иначе ветку с тем же именем. *Force with lease* - это *--force-with-lease*:
он отмечен, когда ветка разошлась со своей upstream-веткой после amend или
reword, сделанного здесь; если она разошлась по другой причине, потому что
кто-то другой отправил коммиты, он не отмечен, и первая строка говорит об
этом. Push без lease не делается никогда. *Set upstream* - это *-u*, он
отмечен для ветки без upstream. *Include tags* - это *--follow-tags*:
аннотированные теги отправляемых коммитов. **Enter** отправляет, **Esc**
отменяет; пробел выбирает удаленный репозиторий.

Пока push, pull или fetch идет в терминале, другой не запускается; закрытие
окна терминала или завершение его оболочки прекращает ожидание.

**Shift-F7**, **b**
: Ветки: локальные, ветки удаленных репозиториев и, если отмечено, теги;
сначала текущая, затем ветки с самыми свежими последними коммитами. В строке
- имя, сколько коммитов есть у ветки и нет у текущей и наоборот (в git 2.41
и новее), как давно был ее последний коммит, его автор и тема.

Набранное идет в фильтр: ветка остается, если каждое слово найдено, без
учета регистра, в ее имени или в авторе или теме ее последнего коммита;
сначала идут ветки, найденные по имени, затем более новые. Если отмечен
*Extended*, слово ищется еще и в авторе и всем сообщении собственных
коммитов ветки, тех, которых нет в *main* или *master*, а тема - это тема
коммита, в котором оно нашлось; *main* и *master* ищутся только по имени.
Эти коммиты читаются при первом использовании: в репозитории с множеством
веток, далеко ушедших от *main*, их много. **Up**, **Down**, **PgUp**,
**PgDn** двигаются по списку; после переключения флажка его клавишей
клавиши остаются у фильтра.

**Enter** переключается на ветку (*git switch*): на ветку удаленного
репозитория - через локальную ветку с ее именем, которая создается и
отслеживает ее, если ее нет, на тег - с отсоединенным HEAD; если git
отказывает, например из-за изменений, которые потерялись бы при
переключении, ничего не меняется. **F7** создает новую ветку от той, что под
курсором, **F8** удаляет локальную ветку после вопроса, и еще раз спрашивает,
если она не слита, **F3** показывает коммиты, которые в ней есть, а в текущей
нет, и наоборот, и файлы, которые она меняет с момента расхождения. **Esc**
закрывает окно.

**F1**
: Эта справка.

**Esc**, **F10**
: Выход из диффа, из файлов коммита, иначе закрытие окна Git; при *coole -G*
вместе с ним завершается редактор.

**Вкладка Status**

Два списка: изменения, не добавленные в индекс, включая файлы, которые git
не отслеживает (помечены *?*), и изменения в индексе для следующего коммита.
Файл, слияние которого дало конфликт, помечен *U*.

**Enter**, **Space**
: Добавить файл в индекс или убрать из него.

**a**
: Добавить в индекс все изменения или убрать их все.

**F2**, **c**
: К сообщению следующего коммита, слева вверху; **F2** там делает коммит
того, что в индексе, а если в индексе ничего нет, сначала предлагает
добавить все.

**F3**, **A**
: Исправить последний коммит тем, что в индексе, и его сообщение (amend): его
сообщение занимает место сообщения следующего коммита, пока amend не сделан.

**F4**, **e**
: Открыть файл в окне редактора на весь экран; его закрытие, а также **Esc**
и **F10** там, возвращают в окно Git.

**F8**, **d**, **Delete**
: Отменить изменение файла в рабочем дереве после вопроса: файл, который git
отслеживает, возвращается к состоянию индекса, а файл, который git не
отслеживает или только добавлен через *git add -N*, удаляется.

**Вкладка Log**

Коммиты ветки, сначала самые новые, с ветками и тегами на них; справа
показывается коммит: автор, даты, сообщение и файлы, которые он меняет.
Коммиты читаются по 2000: когда курсор уходит ниже последнего прочитанного
или нажата **End** на нем, читаются следующие; пока прочитаны не все,
заголовок говорит об этом, например *Commits (2000+)*.

**Enter**
: Файлы коммита; первая строка - сам коммит. Enter на файле передает
клавиши его диффу, *e* открывает файл рабочего дерева, Left или Esc
возвращает к коммитам.

**F4**, **r**
: Дать коммиту другое сообщение (reword): оно занимает место сообщения
следующего коммита, а под ним файлы коммита, пока reword не сделан.

**Вкладка Graph**

Коммиты веток, прочитанные как на Log, нарисованные как в *git-graph*: каждая
ветка в своем столбце, сверху вниз от ее последнего коммита до коммита, от
которого она отошла. Столбцы идут слева: *main* или *master*, *develop*,
*release*, *hotfix*, затем остальные ветки, ветки удаленных репозиториев
после локальных, затем слитые и удаленные ветки, названные по темам их
слияний ("Merge branch 'x'"). Столбец снова занимает ветка ниже. Слияние -
полый узел, а линия ветки, которую оно приняло, входит в него со стрелкой;
у ветки, отошедшей от коммита, линия кончается в строке этого коммита или в
своей строке над ним, если там проходит линия слияния. Список занимает
половину ширины экрана; ветки, которые не помещаются, обрезаются, справа от
графа ставится метка, а кнопка рамки отдает списку весь экран.

У веток есть цвета: *main* синий, *develop* желтый, *release* зеленый,
*hotfix* красный, остальные по очереди, шестнадцать цветов на терминале с
256 цветами и восемь на терминале с 16. Ссылки коммита - в цвете его ветки,
теги - в цвете коммитов. Строка курсора - в цвете выделения.

Что читает граф, показано справа в строке *Commits*; щелчок по ней или *v*
дает выбрать из списка, а выбор сохраняется в настройках до следующего
раза:

- *Current*: только коммиты HEAD, те же, что на Log;
- *Local*: локальные ветки, теги и HEAD;
- *Local+remote*, по умолчанию: еще и ветки удаленных репозиториев;
- *All*: все ссылки, в том числе созданные fetch'ем pull request'ов
  (*refs/pr/...*) и stash, а коммиты вне веток - на линии без имени.

Enter открывает файлы коммита, как на Log, Esc или Left возвращает к
графу. F4 или *r* дает коммиту другое сообщение, только если он на текущей
ветке.

Линии - это линии рамок скина. Секция *[git-graph]* скина может задать
графу свои линии, например скругленные углы, и цвета:

```
[git-graph]
    lefttop = <угол слева вверху>
    righttop = <угол справа вверху>
    leftbottom = <угол слева внизу>
    rightbottom = <угол справа внизу>
    commit = *
    merge = o
    rail = (
    others = magenta;cyan;brightmagenta;brightcyan
```

Ключи линий те же, что в *[Lines]*: *vert*, *horiz*, *lefttop*, *righttop*,
*leftbottom*, *rightbottom*, *leftmiddle*, *rightmiddle*, *topmiddle*,
*bottommiddle*, *cross*; остальные ключи - *commit*, *merge*, *arrow-left*,
*arrow-right* и *more*, метка обрезанных веток. *rail* ставит коммит рядом с
линией его ветки, после этого символа, а не на нее; слияние остается на
своей линии. С *rail = (* слитая ветка из трех коммитов выглядит так:

```
o<+       Merge branch 'x'
| (*      the third
| (*      the second
| (*      the first
+-+
```

Цвета - *main*, *develop*, *release*, *hotfix* и *others*, через *;*. Символ
задается один; на 8-битном терминале символ не из ASCII не принимается, и
используются рамки скина.

**Сообщение коммита**

Оно пишется в окне редактора, в файле *COOLE_EDITMSG* в каталоге git
репозитория (*COOLE_AMEND_EDITMSG* для amend, *COOLE_REWORD_EDITMSG* для
reword). В окне Git всегда есть сообщение следующего коммита: его можно
писать когда угодно, до или после добавления файлов в индекс. Amend или
reword занимает его место, пока не сделан, а написанное сообщение коммита
возвращается после него; оно сохраняется и при закрытии окна Git. Сообщение
amend или reword уже заполнено; под ним, после строк, начинающихся с *#*,
показано, что коммитится. Эти строки отбрасываются.

**Сохранение** файла (**F2**) делает коммит; его место занимает пустое
сообщение следующего коммита. Если в индексе ничего нет, плагин сначала
предлагает добавить все, если только слияние не оставило файлы с
конфликтами. Amend или reword не делается, если HEAD сдвинулся с начала
сообщения, после pull или коммита в терминале: окно нужно закрыть и начать
amend или reword заново. Пустое сообщение ничего не коммитит. Если git
отказывает, например хук *commit-msg*, или коммитить нечего, показывается
его ответ, а окно остается, чтобы сохранить еще раз, и при закрытии окна
сообщение остается для следующего коммита. Закрытие окна сообщения, которое
не было отвергнуто, выбрасывает его; **F2** в списках возвращает пустое.
При выходе из редактора сообщение следующего коммита сохраняется до
следующего раза, а сообщение amend или reword - нет.

Коммит и amend - это *git commit*, с хуками. Reword заново делает коммит с
новым сообщением и теми же файлами, а коммиты после него - заново поверх
него, как сделал бы *git rebase*; индекс и рабочее дерево не трогаются, хуки
не запускаются. Коммиту, после которого есть слияние, здесь нельзя дать
другое сообщение. Пересозданные коммиты теряют подписи.

**Меню сообщения: F11**

В окне сообщения, одного из этих файлов или *COMMIT_EDITMSG*, когда редактор
служит редактором *git commit*, **F11** открывает свое меню вместо меню
пользователя. Его пункты берутся из *~/.config/coole/git-menu.ini*, иначе из
*git-menu.ini* coole в каталоге его настроек (*/etc/coole*), это пункты ниже;
**m** в нем создает файл пользователя из него и открывает его. Трейлеры
добавляются в конец сообщения, перед строками, которые git отбрасывает,
после пустой строки или в имеющийся блок трейлеров, один раз; **Ctrl-U**
отменяет то, что сделал пункт.

**s**
: *Signed-off-by:* с именем и почтой из *git config*.

**c**
: *Co-authored-by:* с автором, выбранным из истории.

**f**
: *Fixes:* с запрошенным коммитом, как *Fixes: 1e1573e28a1b ("subject")*.

**r**
: Текущее сообщение коммита вместо написанного: для reword и amend.

**d**
: Дифф коммита, которому дается сообщение, или того, что коммитится, в окне
просмотрщика справа.

**l**
: Проверить вид сообщения: длину темы, точку в ее конце, пустую вторую
строку, строки тела длиннее 72 колонок.

**g**
: Сгенерировать сообщение с помощью ИИ: команда из *ai.ini* пишет его по
диффу; оно заменяет сообщение, трейлеры остаются. Если для коммита в индексе
ничего нет, сначала предлагается добавить все, как делает **F2**; если диффа
нет совсем, команда не запускается.

**p**
: Править промпт ИИ: *ai.ini* в окне редактора на весь экран, на промпте
для вида сообщения (*prompt-reword* для reword) или на *prompt*, **Esc** -
назад; это файл проекта, если в нем есть промпт, иначе файл пользователя,
который создается из *ai.ini* coole, если его нет.

**m**
: Править это меню: *~/.config/coole/git-menu.ini* в окне редактора,
созданный из меню coole, если его нет; **Esc** - назад к сообщению.

**git-menu.ini**

Для каждого пункта - группа, названная по его клавише; пункты идут в порядке
групп:

```
[s]
action = signoff

[x]
label = Reviewed-by: a reviewer
command = echo 'Reviewed-by: A Reviewer <a@example.org>'
output = trailer
```

*label*
: Что показывает меню; у действия есть своя подпись.

*action*
: Действие плагина: *signoff*, *coauthor*, *fixes*, *restore*, *diff*,
*check*, *generate*, *prompt*, *menu* - пункты выше.

*command*
: Вместо действия - команда, которую *sh* запускает в рабочем дереве:
сообщение идет ей на стандартный ввод, а *COOLE_GIT_MODE* и
*COOLE_GIT_COMMIT* - в окружение, как для команды из *ai.ini*. Она берется
как написана: обратная косая черта в ней - для *sh*.

*output*
: Что делать с выводом команды: *trailer* - каждая строка становится
трейлером в конце сообщения; *replace* - заменяет сообщение, трейлеры
остаются; *insert* - вставляется у курсора, по умолчанию; *show* - в окне
просмотрщика справа; *none*.

*modes*
: *commit*, *amend*, *reword* через *;*: для каких сообщений пункт есть в
меню; без этого ключа - для всех.

Репозиторий не может задать меню: его команды выполняли бы то, что
написал автор репозитория.

**ai.ini**

Команда, которая пишет сообщения, задается в группе *[commit-message]* файла
*~/.config/coole/ai.ini*:

```
[commit-message]
command = claude -p --tools "" --no-session-persistence
prompt = Write the git commit message for the changes below ...
input = diff
```

*--tools ""* не оставляет *claude* инструментов: он пишет текст и больше
ничего не делает. Команда может передать не только дифф, но и последние
сообщения репозитория, ради их стиля:

```
command = { cat; echo; echo 'The last messages:'; git log -n 8 --format='%B---' ${COOLE_GIT_COMMIT:+$COOLE_GIT_COMMIT^}; } | claude -p --tools ""
```

Команда получает *COOLE_GIT_MODE* - *commit*, *amend* или *reword* - и
*COOLE_GIT_COMMIT*, коммит для amend или reword, пустой для коммита:
*${COOLE_GIT_COMMIT:+$COOLE_GIT_COMMIT^}* выше - это история до этого
коммита, чтобы его собственное сообщение не служило образцом стиля.

Значения *ai.ini* читаются так, как GLib читает свои key-файлы: обратная
косая черта начинает там escape-последовательность (*\\n* - перевод строки),
а *%* не значит ничего особенного.

*command*
: Запускается *sh* в рабочем дереве. Читает промпт и дифф со стандартного
ввода и печатает сообщение: *claude -p*, другой агент, запущенный так же,
или ваш собственный скрипт.

*prompt*
: О чем команду просят сначала; без него - промпт coole для темы в 50
символов и тела с переносом на 72 колонках.

*prompt-reword*, *prompt-amend*, *prompt-commit*
: Промпт для этого вида сообщения, раньше *prompt*. Для reword команда
получает коммит с его нынешним сообщением; без обоих ключей промпт coole
для reword просит для него сообщение получше.

*input*
: *diff*, по умолчанию: дифф после промпта; *none*: только промпт.

У проекта могут быть свои промпты и input в группе *[commit-message]* файла
*.coole/ai.ini* в его рабочем дереве, и они идут первыми. Команды он не
задает: команда, записанная в репозитории, выполняла бы то, что написал его
автор. Промпты coole лежат в его *ai.ini* в каталоге его настроек
(*/etc/coole*) и идут последними; команды там тоже нет.

Редактор ждет команду, показывая на экране сообщение с ней. Он ничего не
знает о ключах и токенах: команда входит в систему так же, как когда
запущена сама, и получает окружение редактора. Ключ хранится в окружении или
в файле, который читает команда, но никогда в *ai.ini*. Дифф уходит тому
сервису, который вызывает команда.

Файлы *COMMIT_EDITMSG*, файлы coole, *MERGE_MSG* и *TAG_EDITMSG* раскрашены
как сообщения git: строки, которые git отбрасывает, трейлеры вроде
*Signed-off-by:* и номера задач.

**Из файлового менеджера**

Панель git в mc или меню пользователя запускает редактор для одного дела и
получает управление обратно, когда он завершится:

*coole -G* каталог
: Окно Git; его закрытие (**F10**) завершает редактор.

*coole -G* каталог *--git-log*
: То же, на журнале.

*coole -G* каталог *--git-show* коммит
: То же, на файлах и диффах этого коммита.

*coole -G* каталог *--git-commit*
: Окно Git с сообщением коммита того, что в индексе; редактор завершается,
когда коммит сделан или когда окно сообщения закрыто. *--git-amend*
исправляет последний коммит, *--git-reword* коммит дает этому коммиту
другое сообщение, с файлами коммита под ним.

Без *-G* каталог они работают в текущем каталоге. Окна, которые были у
проекта в прошлый раз, его дерево и панель отладчика, не показываются, а то,
что оставляет редактор, запущенный так, не сохраняется для проекта. Плагины
проекта тоже не запускаются: project, build, debugger, ctags и etags, с их
меню и окнами; **Настройки -> Управление плагинами** не затрагивается.

**Клавиши**

Это клавиши по умолчанию; их можно изменить в **Настройки -> Привязки
клавиш -> Редактор -> Git** или в секции *[git]* раскладки клавиш.

**Alt-Shift-C**
: Окно Git на вкладке Status.

**Alt-Shift-L**
: Окно Git на вкладке Log.

*GitCommit*
: Коммит того, что в индексе, из любого окна; клавиши по умолчанию нет.
**Команда -> Git commit...** делает то же.
